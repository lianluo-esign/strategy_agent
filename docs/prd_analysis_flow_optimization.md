# 产品需求文档 (PRD) - 分析流程优化

## 文档信息
- **项目名称**: BTC-FDUSD流动性分析agent
- **功能模块**: 分析流程优化
- **文档版本**: v1.0
- **创建日期**: 2025-10-27
- **负责人**: AI开发团队

## 1. 项目概述

### 1.1 背景
当前BTC-FDUSD流动性分析agent存在多个关键问题，导致分析流程不稳定、输出格式不正确、性能低下。基于用户反馈和日志分析，需要进行全面的分析流程优化。

### 1.2 问题陈述
从日志分析中发现的主要问题：

1. **JSON解析失败**: 统一DeepSeek分析器无法正确解析AI返回的JSON数据
2. **输出格式错误**: 系统应返回简单的交易参数JSON，但实际返回复杂的分析数据
3. **分析模式混乱**: 同时存在统一模式和传统模式，造成不必要的复杂性
4. **错误处理不足**: JSON解析失败时回退到原始内容，无法生成有效的交易信号
5. **数据处理冗余**: 多次处理相同数据，效率低下

### 1.3 目标用户
- 高频做市交易系统
- 自动化交易执行模块
- 风险管理和监控系统

## 2. 功能需求

### 2.1 核心功能优化

#### 2.1.1 简化分析流程
**需求描述**: 重构分析流程，确保清晰的三步处理模式

**输入**:
- Redis中的订单簿深度数据
- Redis中的历史交易数据
- DeepSeek API配置

**处理步骤**:
1. **初始化阶段**: 配置分析器，验证依赖服务
2. **数据聚合阶段**: 从Redis读取并聚合历史数据
3. **AI分析阶段**: 将聚合后的数据发送给DeepSeek进行分析

**输出**:
- 标准JSON格式的交易参数: `{"grid_delta": 2.0, "grid_quantity": 0.001, "active_side": "Buy"}`

#### 2.1.2 修复JSON解析问题
**需求描述**: 确保DeepSeek API响应能够被正确解析为JSON格式

**技术要求**:
- 改进提示词设计，确保AI返回纯净的JSON
- 实现多层JSON解析验证机制
- 添加JSON格式修复和重试逻辑
- 实现优雅的降级处理策略

#### 2.1.3 统一输出格式
**需求描述**: 所有分析结果必须统一为标准的三字段JSON格式

**输出格式规范**:
```json
{
    "grid_delta": 2.0,        // 交易价差 (范围: 0.1-100.0)
    "grid_quantity": 0.001,   // 挂单量 (范围: 0.0001-10.0)
    "active_side": "Buy"     // 交易方向 ("Buy" 或 "Sell")
}
```

### 2.2 技术需求

#### 2.2.1 性能优化
- **响应时间**: 整个分析流程应在60秒内完成
- **内存使用**: 优化内存占用，避免数据冗余
- **并发处理**: 支持多个交易对的并发分析

#### 2.2.2 可靠性提升
- **错误恢复**: 实现自动重试和降级机制
- **数据验证**: 严格验证输入和输出数据格式
- **监控告警**: 添加详细的日志和错误监控

#### 2.2.3 可维护性改进
- **代码简化**: 移除冗余的分析模式，统一为单一流程
- **配置管理**: 集中化配置参数管理
- **测试覆盖**: 达到90%以上的测试覆盖率

## 3. 技术规格

### 3.1 系统架构
```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│   Redis数据存储  │    │   数据聚合器      │    │  DeepSeek AI    │
│                 │    │                  │    │     分析器       │
│ - 订单簿深度数据  │───▶│ - 数据读取和聚合   │───▶│                 │
│ - 历史交易数据    │    │ - 数据验证和清洗   │    │ - AI分析处理     │
│                 │    │ - 格式转换        │    │ - JSON生成      │
└─────────────────┘    └──────────────────┘    └─────────────────┘
                                                        │
                                                        ▼
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│   交易执行系统   │◀───│   结果验证器      │◀───│   输出格式化器   │
│                 │    │                  │    │                 │
│ - 参数验证        │    │ - JSON格式验证    │    │ - 标准JSON输出   │
│ - 交易执行        │    │ - 参数范围检查    │    │ - 错误处理       │
│                 │    │ - 异常处理        │    │                 │
└─────────────────┘    └──────────────────┘    └─────────────────┘
```

### 3.2 数据流程

#### 3.2.1 数据输入规格
**订单簿数据**:
- 买盘数据: `Dict[Decimal, Decimal]` (价格 → 数量)
- 卖盘数据: `Dict[Decimal, Decimal]` (价格 → 数量)
- 数据深度: 至少包含前5000档价位

**交易数据**:
- 时间范围: 最近24小时 (1440分钟)
- 数据点数量: 至少10000个交易记录
- 数据格式: `List[TradeData]`

#### 3.2.2 数据处理规格
**价格聚合**:
- 聚合精度: $1.0 (可配置)
- 最大价格级别: 5000
- 聚合算法: 按价格区间合并数量

**Volume Profile聚合**:
- 聚合精度: $10.0 (可配置)
- 最小成交量阈值: 0.1
- POC计算: 基于成交量加权平均

#### 3.2.3 AI分析规格
**提示词设计**:
- 角色定义: 专业的加密货币市场分析师
- 任务描述: 分析市场数据并生成交易参数
- 输出要求: 严格的三字段JSON格式

**模型配置**:
- 模型: deepseek-chat
- 最大令牌: 6000
- 温度: 0.1
- 超时: 90秒

### 3.3 错误处理规格

#### 3.3.1 JSON解析错误
```python
# 多层解析策略
1. 直接解析完整JSON
2. 提取JSON片段解析
3. 正则表达式提取修复
4. 降级到默认参数
```

#### 3.3.2 API调用错误
```python
# 重试机制
- 最大重试次数: 3次
- 退避策略: 指数退避 (1s, 2s, 4s)
- 超时设置: 连接30s, 读取90s
```

#### 3.3.3 数据验证错误
```python
# 验证规则
- grid_delta: 0.1 ≤ value ≤ 100.0
- grid_quantity: 0.0001 ≤ value ≤ 10.0
- active_side: 只能是 "Buy" 或 "Sell"
```

## 6. 风险评估与缓解

### 6.1 技术风险

#### 6.1.1 API依赖风险
**风险描述**: DeepSeek API服务不稳定或响应格式变化
**缓解措施**:
- 实现多层降级策略
- 添加API响应监控
- 准备备用AI服务方案

#### 6.1.2 性能风险
**风险描述**: 大量数据处理导致性能瓶颈
**缓解措施**:
- 实现数据分批处理
- 优化聚合算法
- 添加性能监控

#### 6.1.3 数据质量风险
**风险描述**: Redis中数据不完整或格式错误
**缓解措施**:
- 添加数据验证机制
- 实现数据备份策略
- 建立数据质量监控

### 6.2 业务风险

#### 6.2.1 交易决策风险
**风险描述**: 错误的分析结果导致交易损失
**缓解措施**:
- 严格的参数验证
- 多层检查机制
- 人工审核流程

#### 6.2.2 系统稳定性风险
**风险描述**: 系统故障影响交易执行
**缓解措施**:
- 实现高可用架构
- 添加故障转移机制
- 建立监控告警系统
