# 产品需求文档 (PRD)
# 高频交易指导事件发布功能

## 1. 功能概述

将现有的Unified AI Analysis功能扩展，不仅输出市场分析结果，还要生成具体的交易指导事件，通过Redis channel发布给外部高频交易执行器，实现AI驱动的自动化交易闭环。

## 2. 业务背景

- **现状**：Unified AI Analysis能够分析市场结构，输出支撑阻力位分析
- **目标**：将AI分析转化为具体的交易指导，实现自动化的高频交易
- **价值**：通过AI分析指导高频交易，提高交易决策的准确性和时效性

## 3. 核心功能需求

### 3.1 交易指导生成
- **输入**：depth_snapshot + trades_window数据
- **处理**：DeepSeek AI分析市场趋势和强度
- **输出**：JSON格式的交易指导事件

### 3.2 事件格式规范
```json
{
  "grid_delta": 2.0,       // 交易价差
  "grid_quantity": 0.001,   // 挂单量
  "active_side": "Buy"      // 交易方向 (Buy/Sell)
}
```

### 3.3 Redis事件发布
- **Channel**：`hft_grid_strategy_params`
- **目标**：外部高频交易执行器
- **频率**：每分钟一次（与AI分析频率一致）
- **可靠性**：支持重试机制和错误处理

## 4. 技术规格

### 4.1 配置要求
```yaml
trading_event_publisher:
  enable: true                          # 启用/禁用功能
  redis:
    host: "trading-server.example.com"   # 外部Redis服务器
    port: 6379                          # Redis端口
    db: 0                               # Redis数据库
    password: "your_password"           # Redis密码（可选）
    channel: "hft_grid_strategy_params" # 发布Channel
    timeout: 5                         # 连接超时时间
    max_retries: 3                      # 最大重试次数
  validation:
    min_grid_delta: 0.1                # 最小价差
    max_grid_delta: 100.0              # 最大价差
    min_grid_quantity: 0.0001           # 最小挂单量
    max_grid_quantity: 10.0             # 最大挂单量
```

### 4.2 AI提示词优化
- **当前**：输出市场分析结果（支撑阻力位、流动性区域等）
- **目标**：输出交易指导事件JSON + 市场分析总结
- **平衡**：保持原有的市场分析功能，增加交易决策输出

### 4.3 数据验证规则
- **结构验证**：JSON格式必须包含所有必需字段
- **数值验证**：价差和挂单量必须在合理范围内
- **业务验证**：交易方向必须基于市场分析逻辑

## 5. 实现方案

### 5.1 架构设计
```
Unified AI Analysis → Trading Event Publisher → Redis Channel → Trading Executor
```

### 5.2 核心组件
1. **TradingEventPublisher**：交易事件发布器
2. **EventValidator**：事件验证器
3. **RedisPublisher**：Redis发布器
4. **EnhancedPrompt**：增强的AI提示词

### 5.3 数据流程
1. AI分析市场数据
2. 生成交易指导事件JSON
3. 验证事件格式和数值
4. 发布到Redis Channel
5. 外部交易器接收并执行

## 6. 验收标准

### 6.1 功能验收
- [ ] AI能够生成符合格式的交易指导事件
- [ ] 事件数据通过验证规则检查
- [ ] 成功发布到指定Redis Channel
- [ ] 支持启用/禁用配置
- [ ] 错误处理和重试机制正常工作

### 6.2 性能验收
- [ ] 事件发布延迟 < 1秒
- [ ] 支持100%事件发布成功率（网络正常情况下）
- [ ] 内存使用稳定，无泄漏

### 6.3 可靠性验收
- [ ] Redis连接失败时有重试机制
- [ ] JSON验证失败时有错误日志
- [ ] 网络异常时能够优雅降级

## 7. 风险评估

### 7.1 技术风险
- **依赖风险**：外部Redis服务器的稳定性
- **网络风险**：网络延迟或中断影响事件发布
- **数据风险**：AI输出格式不稳定

### 7.2 缓解措施
- 实现重试机制和超时控制
- 添加详细的错误日志和监控
- 设置合理的数据验证规则

### 7.3 业务风险
- **交易风险**：AI分析错误导致不当交易指导
- **性能风险**：高频事件发布影响系统性能

### 7.4 缓解措施
- 保持原有市场分析功能作为参考
- 实现配置开关，支持快速禁用
- 添加事件监控和告警机制
